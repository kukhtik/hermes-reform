# F1.5 Implementation Notes

## What was implemented

### New functions in `gateway/authz_mixin.py`

1. `_normalize_telegram_allowed_users(raw: str) -> tuple[list[str], list[str]]`
   - Splits comma-separated TELEGRAM_ALLOWED_USERS on commas
   - Strips whitespace
   - Drops empty parts silently
   - Returns `(normalized_ids, garbage_entries)` where garbage = entries that
     don't look like numeric Telegram IDs (`^\d+$`) or @-prefixed usernames
     (`^@[\w]+$`)

2. `_gateway_policy_warnings() -> list[logging.LogRecord]`
   - Does NOT emit logs itself — returns `LogRecord` objects so tests can
     inspect level and message without requiring log-capture fixtures
   - Call site (`gateway/run.py`) dispatches at CRITICAL or WARNING level
   - Three checks:
     **(a)** `GATEWAY_ALLOW_ALL_USERS=true` → CRITICAL
     **(b)** Per-platform `*_ALLOW_ALL_USERS=true` → CRITICAL (18 platforms)
     **(c)** Platform token set but no allowlist + no global allowlist → WARNING
   - Telearam garbage detection: WARNING with count + first-10 items

### Call site in `gateway/run.py` (line ~12614)

In `GatewayRunner.start()`, after profile log and before
`write_runtime_status`. Wrapped in try/except → logs at DEBUG on failure
(so a broken validator never crashes gateway startup).

## Design decisions

- **WARN-only, no runtime behavior change** — the validator only reads env vars
  and returns log records; it does not modify any authz outcome
- **LogRecord return pattern** — `_gateway_policy_warnings()` returns records
  instead of emitting directly. This makes it unit-testable without any
  log-capture fixtures, and keeps the logging level explicit at the call site
- **`_normalize_telegram_allowed_users` is public** (no leading `_`) so it
  can be imported directly by tests that want to test the normalization in
  isolation
- **Per-platform token detection** — the open-policy warning fires when a
  platform token is present (proving the platform is configured) but neither a
  per-platform nor global allowlist is set. This means: no WARNING when only
  `TELEGRAM_ALLOWED_USERS` is set (it's scoped to that platform)
- **All 18 per-platform `ALLOW_ALL` vars** checked at startup, not just the
  global flag

## Validation branches covered

1. `GATEWAY_ALLOW_ALL_USERS=true` → CRITICAL ✓
2. `TELEGRAM_ALLOW_ALL_USERS=true/yes/1` → CRITICAL ✓
3. `TELEGRAM_BOT_TOKEN` present + no allowlist → WARNING ✓
4. TELEGRAM_ALLOWED_USERS with numeric IDs → normalized ✓
5. TELEGRAM_ALLOWED_USERS with `@username` → normalized ✓
6. TELEGRAM_ALLOWED_USERS with garbage (emails, SQL, random) → WARNING ✓
7. TELEGRAM_ALLOWED_USERS empty parts → silently ignored ✓
8. All of the above with `=false` / unset → no CRITICAL ✓
